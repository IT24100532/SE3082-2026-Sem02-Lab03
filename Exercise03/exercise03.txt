Exercise 3: S = sum_{i=1..N} [ i - i^2 + sqrt(2 x (i + 1)) ], N = 10,000,000
Run on: Debian Linux container (Docker), gcc 14.2, 8 logical cpus. Build: make   Run: make run
(from resources/q2.png; "2x(i+1)" means 2 times (i + 1))

Compile and run:  gcc -fopenmp -O2 sum_serial.c -o sum_serial -lm
                  gcc -fopenmp -O2 sum_parallel.c -o sum_parallel -lm

Results:
version           threads   S                time (s)
serial               -      -3.333333e+20    0.0098
parallel             1      -3.333333e+20    0.0356
parallel             2      -1.605442e+20    0.0189
parallel             4      -1.008002e+20    0.0099
parallel             8      -1.143996e+20    0.0160
parallel            16      -1.307740e+20    0.0150

The serial answer is about -N^3/3 = -3.33e20, which is right (the -i^2 term dominates).
The parallel answers are WRONG for 2+ threads, for the same reason as Exercise 2:
S is a shared variable updated by all threads without protection (data race), so
most threads' partial sums are lost.

There is also no real speedup: the serial loop takes only 10 ms, so starting and
managing the threads costs about as much as the work itself. The 1-thread parallel
version is even slower than serial, because of the OpenMP overhead.
A bigger EC2 instance (question 1–2) needs your AWS account; run "make run" there.
